# 撰写"研究方案-拟采取的研究方法"

## 这个skill做什么

帮助用户撰写科研申报书中"拟采取的研究方法"部分。这是整个申报书技术含量最高的部分，需要将研究内容转化为具体的技术方案，包含问题建模、算法设计、数学推导、实验方案等。

核心挑战：既要展现技术深度（让评审看到"这个人确实有办法解决问题"），又要保持可读性（让非同行评审也能理解技术路线的合理性）。

## 输入要求

### 必需输入
1. **研究目标、研究内容和关键问题**（已完成的部分）：研究方法必须对应这些内容
2. **各研究内容的技术思路**：每个研究内容打算用什么方法解决

### 重要输入
3. **已有的数学模型/公式**：如果已有初步的技术方案，优先使用
4. **实验方案概要**：打算在什么数据集、什么模型上做实验
5. **技术路线图**：各研究内容之间的关系（如有）

## 撰写流程

### 第一步：构建整体技术路线

在详细展开每个方法之前，先用1段概述整体研究思路：

**写法要点**：
- 用1-2句话概括总体技术路线（如"训练阶段前置净化—推理过程安全约束—测试时补充防护"）
- 用"先...再...最后..."串联各研究阶段
- 可配合技术路线图（如果申报书支持图片）

**句式框架**：
```
本项目面向[问题场景]，围绕[A、B、C]等关键环节开展研究。
整体上，拟采取"[路线1]—[路线2]—[路线3]"的研究思路：
先从[阶段1]入手，研究[方法1]；再从[阶段2]入手，研究[方法2]；
最后，针对[阶段3]，研究[方法3]。
```

### 第二步：逐条展开研究方法

每条研究方法对应一个研究内容，按以下结构展开：

#### 方法标题

格式："面向[场景/问题]的[方法名称]"

#### 1. 问题建模（约100-200字）

- 描述问题的数学/形式化定义
- 引入必要的符号和记号
- 明确优化目标或求解目标

**典型写法**：
```
[描述场景]，通常基于任务数据集
    Dtrain = {(xi, qi, yi)}_{i=1}^{N}      (公式1)
进行下游适配，其中 xi 表示[含义]，qi 表示[含义]，yi 表示[含义]。
若记[组件]为 f(·)，则标准过程可写为
    min_θ E_{(x,q,y)~D} L(f(x,q), y),      (公式2)
其中 θ 为模型参数，L(·) 为[损失函数]。
```

#### 2. 核心方法设计（约200-400字）

- 详细描述提出的方法/算法
- 包含关键公式推导
- 解释公式的含义和直觉

**公式撰写规范**：
- 每个公式右对齐编号：(1)(2)(3)...
- 公式前应有文字引导（"记为""可表示为""定义为"）
- 公式后应有解释（"其中A表示B，C表示D"）
- 公式之间应有逻辑递进（定义→推导→结果）

#### 3. 方法创新点说明（约50-100字）

- 指出该方法与已有方法的差异
- 强调方法的优势（如"不依赖X""在Y条件下仍有效"）

**典型句式**：
```
该方法的核心在于[核心创新]，
不依赖[已有方法的依赖条件]，
因而更适合[目标场景]。
```

### 第三步：检查方法之间的逻辑关系

确保各研究方法之间形成合理的技术路线：
- 方法1的输出是否是方法2的输入？
- 方法之间的依赖关系是否清晰？
- 整体路线是否完整覆盖了所有研究内容？

## 数学公式撰写规范

### 公式排版
- 独立公式居中，右侧编号 (1)(2)(3)...
- 短公式可嵌入行内（如"记损失函数为 L(θ)"）
- 符号首次出现时必须定义

### 符号规范
- 标量用小写斜体：x, y, z, θ
- 向量用小写粗体：**x**, **q**
- 矩阵用大写斜体或粗体：A, E
- 集合用花体或大写：D, S
- 函数/算子用正体或斜体：L(·), f(·), E[·]
- 上下标含义明确，避免二义性

### 公式解释模式
```
[引导语]可表示为
    [公式]                                    (编号)
其中 [符号1] 表示 [含义1]，[符号2] 表示 [含义2]。
```

## 写作风格规范

### 语言风格
- **技术精确**：方法描述要足够具体，让同行能理解技术路线
- **逻辑清晰**：从问题定义到方法设计，推导链完整
- **适度使用数学**：公式服务于方法表达，不是为了炫技

### 深度控制
- **不要过浅**：不能只说"采用深度学习方法"，要有具体的模型/算法设计
- **不要过深**：避免长篇推导和证明，抓住核心创新公式即可
- **评审友好**：让评审能在5-10分钟内理解每个方法的核心思路

### 图表使用
- 如申报书允许，适当使用技术路线图、算法流程图、框架图
- 每张图应有明确的标题和说明
- 图应帮助理解方法结构，不是装饰

### 字数参考
- 整体技术路线概述：约200-300字
- 每条研究方法：约500-1000字
- 总计约2000-5000字（视申报级别和研究复杂度调整）
- 一般包含4条研究方法

## 输出格式

```
2. 拟采取的研究方法
[整体技术路线概述段落]

2.1.1 面向[场景1]的[方法1]
[问题建模]
[核心方法设计]
[方法创新说明]

2.1.2 面向[场景2]的[方法2]
[问题建模]
[核心方法设计]
[方法创新说明]

...

2.1.N 面向[场景N]的[方法N]
[问题建模]
[核心方法设计]
[方法创新说明]
```

## 注意事项

1. **方法必须对应研究内容**：每条方法应对应"研究内容"部分的一条，不能脱节
2. **数学公式不能有错**：符号一致性、推导正确性是基本功，出错会严重影响评审印象
3. **不要写成实验方案**：这里侧重方法设计，实验细节（数据集、评价指标等）可以简述
4. **方法要有可行性**：提出的方法应有技术可行性，不能是纯理论猜想
5. **与已有方法的区分**：每个方法都应说明与已有方法的不同，避免看起来像是复用
6. **技术路线图**：如有条件，在开头放一张技术路线图能极大提升可读性
