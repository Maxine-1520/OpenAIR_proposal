# 撰写"立项依据-项目的研究目的与意义"

## 这个skill做什么

帮助用户撰写科研申报书中"立项依据-项目的研究目的与意义"部分。这一部分是整个申报书的逻辑起点，需要回答"为什么做这个研究"和"做了有什么用"两个核心问题。

写作的核心挑战在于：不是简单地描述研究背景，而是要构建一条从技术发展趋势到研究问题特殊性，再到具体研究目标的严密论证链，让评审专家在读完后就认同"这个问题确实值得研究，而且非做不可"。

## 输入要求

在开始撰写之前，必须收集以下信息（如果用户没有完整提供，应主动询问）：

### 必需输入
1. **研究主题与方向**：项目研究什么？属于什么学科领域？
2. **核心研究问题**：要解决的具体问题是什么？（即使只有一个粗略的方向也行）
3. **研究对象定位**：在更大的技术/学术谱系中，研究对象处于什么位置？（如：是大模型安全下的多模态安全子方向）

### 重要输入（有则更好，没有可通过调研补充）
4. **文献调研材料**：已有的文献综述、调研文档（如有，优先阅读）
5. **研究方法概要**：打算用什么方法解决问题（帮助论证可行性）
6. **申报类型与级别**：国自然青基/面上、省重点研发、研创项目等（影响论述深度和侧重点）
7. **相关领域对比**：与本项目最相近的已有研究方向是什么？本项目的差异性在哪里？

### 可选输入
8. **前期成果**：团队已有的相关研究成果（帮助定位研究基础）
9. **应用场景**：研究成果的潜在应用领域

## 撰写流程

### 第一步：理解与定位（阅读已有材料）

1. 阅读用户提供的所有材料（文献综述、开题报告、相关文档等）
2. 明确研究对象在技术/学术发展谱系中的定位
3. 如果用户提供了参考文献或调研文档，仔细阅读并提取关键论点和数据

**如果用户没有提供充分的背景材料**，应建议用户先进行文献调研，或使用 academic-search skill 辅助收集相关文献信息。不要凭空编造技术趋势和学术论点。

### 第二步：构建论证框架

按照以下结构搭建论证骨架：

```
1. 项目的研究目的与意义
   1.1 研究目的
       1.1.1 [技术/领域]已成为[更高层次定位]的重要基础/关键能力    ← 宏观趋势
       1.1.2 [本领域问题]具有区别于[相近领域]的特殊性             ← 差异论证
       1.1.3 本项目拟解决的核心问题                                ← 问题凝练
   1.2 研究意义
       1.2.1 有助于深化对[研究对象]本质的认识                      ← 理论意义
       1.2.2 有助于推动[方法/技术]由A转向B                         ← 方法意义
       1.2.3 有助于解决[现实条件]下的现实难题                       ← 实践意义
```

### 第三步：逐节撰写

#### 1.1.1 技术背景与趋势（宏观→聚焦）

**论证目标**：让评审专家理解研究对象的重要性和发展趋势，为后续问题引出铺垫。

**写法要点**：
- 开头用"X已成为Y的重要基础/关键能力"句式定位研究对象的宏观价值
- 用2-3句话概述该领域的快速发展（可引用文献[1-5]支撑）
- 转折到应用方式的变化或新挑战的出现（用"与此同时""然而"过渡）
- 收束到为什么需要关键技术研究（用"因此"总结）

**典型段落结构**：
```
[宏观定位与价值] → [发展趋势概述(+文献引用)] → [应用方式变化/新挑战] → [引出关键技术研究需求]
```

#### 1.1.2 问题特殊性（对比论证）

**论证目标**：证明本领域的问题不是已有研究的简单延伸，有独立的学术价值。

**写法要点**：
- 用"X具有区别于Y的特殊性"作为核心论点
- 从至少两个维度展开特殊性论证（如：失效机理维度、风险类型维度）
- 每个维度采用"Y只涉及A，而X还涉及B"的对比结构
- 引用已有文献支撑对比论述（如[6][7]）
- 可以使用"一方面...另一方面..."展开不同侧面
- 段落结尾回归到"这也是本项目选择X作为研究对象的重要原因"

**关键**：这一节的论证强度直接决定评审专家是否认同研究的必要性。不能只是简单说"这个问题很重要"，而要说清楚"这个问题为什么不同于已有问题、为什么已有的方法不够用"。

#### 1.1.3 拟解决的核心问题（问题凝练）

**论证目标**：清晰列出本项目要解决的具体问题，体现研究的系统性和完整性。

**写法要点**：
- 用"首先...其次...再次..."依次展开3个左右的核心问题
- 每个问题的句式："针对[具体场景/条件]下的[问题类型]，研究[研究内容]，重点[解决/分析][具体目标]"
- 每个问题之间应有逻辑递进关系（如：训练阶段→推理阶段→部署阶段）
- 最后用"总的来看"段落总结整个研究目的，形成完整的研究目标陈述

**典型问题展开**：
```
首先，针对[条件A]下的[风险X]，研究[机理/方法]，重点分析[具体影响]。
    在此基础上，探索[方法/手段]，从[角度]降低[风险]。
其次，针对[条件B]下的[问题Y]，研究[机制/方法]，重点解决[核心难点]。
    使[能力]能够[提升]，提升模型在[场景]中的[性能]。
再次，针对[条件C]下的[挑战Z]，研究[技术/方法]。
    一方面[技术路径A]，另一方面[技术路径B]。
总的来看，本项目的研究目的在于：围绕[研究主题]，针对[问题1]、[问题2]和[问题3]，
    研究[方法1]、[方法2]、[方法3]和[方法4]，形成[最终目标]，为[应用场景]提供[支撑]。
```

#### 1.2.1 理论意义

**论证目标**：阐述研究对学术认知的贡献。

**写法要点**：
- 用"有助于深化对X本质的认识"作为标题
- 先指出当前认识的不足（"当前...仍处于快速发展阶段""...不再只是...而是..."）
- 论述研究如何推进认知（"从现象识别推进到机理分析""从局部到整体"）
- 如有多个层面的理论贡献，用"进一步看"递进展开

#### 1.2.2 方法意义

**论证目标**：阐述研究对方法体系发展的推动。

**写法要点**：
- 用"有助于推动X由A转向B"作为标题，体现方法论的范式转换
- 先指出当前方法的局限性（"停留在单点防御层面"）
- 用"第一...第二...第三..."展开新方法体系的三个层面
- 总结方法路径的价值（"不是围绕某一种攻击现象做局部修补，而是建立连贯方法体系"）

#### 1.2.3 实践意义

**论证目标**：阐述研究对实际应用的推动。

**写法要点**：
- 用"有助于解决X条件下的现实难题"作为标题，紧扣现实约束
- 先描述现实中的痛点场景（"数据来源不可控""部署后不便频繁回炉"）
- 论述研究成果如何应对这些现实约束
- 强调已有研究对实践问题的支撑（"相关研究表明...这些说明X并非无法感知，而是缺乏合适的利用方式"）

### 第四步：审查与优化

完成初稿后，进行以下检查：

1. **论证链完整性**：从背景→特殊性→核心问题是否形成连贯逻辑链？
2. **小标题质量**：每个小标题是否是完整的论点句（而非简单短语）？
3. **逻辑连接词**：段落间是否有"因此""与此同时""进一步看"等连接词？
4. **文献引用**：关键论点是否有文献标记（[1-5]、[6]、[7]等）？
5. **语言风格**：是否庄重、精确、不过度修辞？
6. **字数控制**：总计约2000-3000字

## 写作风格规范

### 语言风格
- **庄重但不空洞**：使用学术论证语言，避免口号式表述和空洞形容词
- **精确论证**：每个论点都有据可依，不泛泛而谈
- **适度使用连接词**：构建论证链而非简单罗列
  - 递进：因此、与此同时、进一步看、从这个意义上讲
  - 转折：然而、但、不过
  - 并列：一方面...另一方面...、首先...其次...再次...
  - 说明：也就是说、具体而言

### 小标题规范
- **必须使用完整的论点句**，而非简单短语
- 好的标题示例：
  - "多模态大语言模型已成为复杂信息处理的重要基础能力"
  - "多模态安全问题具有区别于文本模型的特殊性"
  - "有助于推动多模态安全方法由局部修补转向体系化构建"
- 差的标题示例：
  - "研究背景"
  - "问题分析"
  - "理论意义"

### 论证模式
- **先立后破**：先肯定已有进展或价值，再用转折指出不足或新挑战
- **对比论证**：通过与相近领域的对比突出特殊性
- **递进论证**：从宏观到微观、从现象到机理、从局部到整体

### 字数参考
- 1.1.1 技术背景：约400-500字
- 1.1.2 问题特殊性：约500-600字
- 1.1.3 核心问题：约400-500字
- 1.2.1 理论意义：约300-400字
- 1.2.2 方法意义：约300-400字
- 1.2.3 实践意义：约300-400字
- **总计：约2000-3000字**

## 注意事项

1. **不要编造数据或文献**：如果缺少支撑材料，应提示用户提供或建议进行文献调研
2. **不要写成文献综述**：这一部分是论证"为什么做"，不是综述"别人做了什么"（那是"国内外研究现状"部分的任务）
3. **不要过度自夸**：用客观论证代替主观评价，让逻辑本身说服评审
4. **不要脱离申报级别**：不同级别的申报书对论述深度有不同要求（青基侧重创新性，重点研发侧重系统性）
5. **保持与后续section的逻辑衔接**：这里提出的问题要能在"研究方案"部分得到回应，这里声称的意义要能在"预期成果"部分得到佐证
