# 撰写"（个人）研究方案-可行性分析"

## 这个skill做什么

帮助用户撰写科研申报书中的可行性分析部分。这一部分要回答"这个项目能不能做成"的问题，从前期的技术储备、研究条件和团队支撑三个维度论证项目的可行性。

核心挑战：可行性分析不是简单地说"项目可行"，而是要用具体事实和逻辑让评审专家确信项目有条件、有能力完成。

## 输入要求

### 必需输入
1. **研究目标和研究方法**（已完成的部分）：可行性分析必须围绕这些内容展开
2. **申请人/团队信息**：前期成果、技术能力、实验条件等

### 重要输入
3. **依托单位条件**：实验室、平台、设备等
4. **团队构成**：指导教师、合作者等
5. **申报级别**：不同级别对可行性论证的要求不同

## 撰写流程

### 第一步：确定可行性论证结构

根据申报级别和项目特点，选择合适的论证结构：

**版本A（通用版本，适合大多数项目）**：
```
开篇段：概括项目定位和总体判断
（1）关键技术储备较为扎实
（2）项目研究环境能够满足需要
（3）所在团队支持较为有力
总结段：综合判断
```

**版本B（适合竞争性较强的项目，论述更充分）**：
```
（1）研究目标明确：[聚焦定位]
（2）技术路线科学：[基于前期成果的进一步创新]
（3）研究基础扎实：[高水平学术积累与工程经验]
（4）实验条件优越：[依托平台与协作环境]
（5）风险应对有方：[前瞻性预案]
```

### 第二步：逐条展开论证

#### 开篇段（约100-150字）

```
本项目围绕[研究主题]展开研究，重点关注[A、B、C]等关键问题，
属于[领域定位]的重要前沿方向，研究内容具有较强挑战性。
同时，本项目研究目标明确，技术路线较为清晰，
项目负责人具备较好的前期研究积累，
依托单位具有扎实的研究基础、完善的实验条件和有力的团队支撑，
能够为项目顺利实施提供保障。项目的可行性主要体现在以下N个方面。
```

#### 每条可行性论证的写法

**关键技术储备**（约150-300字）：
- 列举与项目直接相关的前期研究成果
- 说明已掌握的关键技术
- 指出前期工作与本项目的关系

**句式参考**：
- "项目申请人在X方面已积累了较为丰富的经验"
- "前期工作中，已在Y方向取得了初步成果"
- "这些前期积累为本项目中Z问题的研究奠定了基础"

**研究环境条件**（约150-300字）：
- 依托单位/实验室的资质和条件
- 硬件设备（GPU集群等）
- 软件平台和数据资源

**团队支撑**（约150-300字）：
- 指导教师的研究方向和成果
- 团队成员的能力和分工
- 协作单位和外部支持

**风险应对**（如需要，约150-300字）：
- 识别可能面临的技术风险
- 提出针对性的预案
- 用"一方面...另一方面..."展开应对措施

#### 总结段（约50-100字）

```
综上所述，本项目拟研究的问题具有明确的现实需求和学术价值，
研究目标清晰，技术路线较为完整；
项目负责人在相关方向已具备较好的研究积累和工程经验，
依托单位能够提供良好的科研平台和实验条件，
所在团队也具备较强的学术与工程支撑能力。
因此，本项目总体上具备较好的研究基础和实施条件，研究方案具有可行性。
```

## 写作风格规范

### 语言风格
- **实事求是**：用事实说话，避免空洞的自信表述
- **有据可依**：每个可行性论点都应有具体的事实支撑
- **适度留余地**：用"较为""较好""基本满足"等适度表述，避免绝对化

### 论证原则
- **针对性**：每条论证都应与项目的研究内容相关
- **具体性**：用具体的事实（论文数量、设备型号等）代替笼统描述
- **逻辑性**：技术储备→研究条件→团队支撑，形成完整的可行性证据链

### 两类版本的适用场景
- **版本A**：适合一般项目（如青基、省基金等），简洁明了
- **版本B**：适合竞争性强的项目（如重点研发、杰青等），论述更充分
- 选择哪种版本应根据申报要求和项目特点决定

### 字数参考
- 每条论证：约150-300字
- 开篇+总结：约150-250字
- **总计：约600-1500字**

## 输出格式

```
2.2 可行性分析
[开篇段]

（1）关键技术储备较为扎实。
[论证内容]

（2）项目研究环境能够满足需要。
[论证内容]

（3）所在团队支持较为有力。
[论证内容]

[总结段]
```

## 注意事项

1. **不能编造条件**：所有设备、成果、团队信息必须真实可查
2. **不要与"研究基础"部分大量重复**：那里侧重"有什么"，这里侧重"这些够不够"
3. **风险应对不是必须的**：根据申报要求决定是否加入
4. **避免空话套话**：每个论证点都应有具体的事实支撑
5. **与项目内容的对应**：论证的可行性应与项目的研究方法和技术路线直接相关
6. **注意"个人"属性**：这一部分应突出申请人/团队的能力，不是泛泛而谈领域的可行性
