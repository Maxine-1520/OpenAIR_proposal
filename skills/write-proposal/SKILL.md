# 科研申报书全流程撰写编排

## 这个skill做什么

编排科研申报书各部分的撰写顺序，管理section之间的依赖关系，协调迭代修订。不直接撰写内容，而是作为总指挥调度以下9个section-level skill：

| 序号 | Skill | 对应section |
|------|-------|------------|
| S1 | `write-research-purpose` | 立项依据-研究目的与意义 |
| S2 | `write-literature-review` | 立项依据-国内外研究现状分析和发展趋势 |
| S3 | `write-application-prospects` | 立项依据-应用前景和学术价值+行业企业实际问题 |
| S4 | `write-references` | 立项依据-参考文献（文献调研） |
| S5 | `write-research-foundation` | 现有研究基础、条件、手段以及指导教师情况 |
| S6 | `write-research-objectives` | 研究方案-研究目标、研究内容和拟解决的关键问题 |
| S7 | `write-research-methods` | 研究方案-拟采取的研究方法 |
| S8 | `write-feasibility` | 研究方案-可行性分析 |
| S9 | `write-innovation-plan` | 研究方案-特色创新点+计划+预期成果 |

另有 `write-key-problems` 可与 S6 协同使用，提供关键问题部分的深度论证。

## 执行前：信息收集

在启动撰写流程之前，必须向用户收集以下基础信息。如果用户未完整提供，应逐项询问：

### 必需信息
1. **研究主题与方向**：项目研究什么？属于什么学科领域？
2. **核心研究问题**：要解决的核心问题是什么？（粗略方向即可，后续会迭代精化）
3. **申报类型与级别**：国自然青基/面上、省重点研发、研创项目等
4. **项目执行期限**：如"2027年1月-2029年12月"

### 重要信息（有则收集，没有后续补充）
5. **已有材料**：开题报告、文献综述、相关论文、前期成果等文件路径
6. **研究方法初步思路**：打算用什么技术路线（如已有想法）
7. **申请人/团队信息**：用于S5（研究基础）和S8（可行性分析）
8. **指导教师信息**：姓名、职称、研究方向、代表性成果

## 依赖关系与执行顺序

### 依赖图

```
S4(文献调研) ────── 持续性任务，贯穿Phase 1-3
     │
     ▼
S2(研究现状) ◄──► S1(研究目的与意义)    ← Phase 1: 互为迭代
     │                   │
     └───────┬───────────┘
             ▼
        S3(应用前景与价值)              ← Phase 2
             │
             ▼
        S6(研究目标/内容/关键问题)       ← Phase 3: 核心枢纽
             │
             ▼
        S7(研究方法)                    ← Phase 4
        ┌────┴────┐
        ▼         ▼
  S9(创新+计划)  S8(可行性分析)          ← Phase 5: 可并行
                  │
                  ▼
              S5(研究基础/条件)           ← 随时可写
```

### 执行阶段

```
Phase 0: 前期准备
  └─ S4 启动文献调研

Phase 1: 立项依据核心（迭代，可循环2-3轮）
  ├─ S2 撰写国内外研究现状
  ├─ S1 撰写研究目的与意义（与S2迭代）
  └─ S4 补充文献

Phase 2: 价值论证
  ├─ S3 撰写应用前景和学术价值
  └─ S4 补充文献

Phase 3: 研究方案纲领
  ├─ S6 撰写研究目标、研究内容和拟解决的关键问题
  └─ Phase 1-2 完结后可对 S1/S2 做最终修订

Phase 4: 研究方法
  ├─ S7 撰写拟采取的研究方法
  └─ S4 最终确认文献引用

Phase 5: 收尾（以下可并行）
  ├─ S9 撰写特色创新点+计划+预期成果
  ├─ S8 撰写可行性分析
  └─ S5 撰写研究基础/条件/指导教师（可在任意Phase准备）

Phase 6: 全文审查
  └─ 检查各section之间的逻辑一致性和衔接
```

## 每个Phase的执行规范

### Phase 0：前期准备

**目标**：建立文献基础，明确研究定位。

**执行步骤**：
1. 阅读用户提供的所有已有材料（开题报告、综述、论文等）
2. 调用 `write-references` skill，启动文献调研
3. 如用户未提供充分材料，配合 `academic-search` skill 进行文献检索
4. 整理初步文献列表，建立引用编号体系

**产出**：初步文献列表，对研究方向的初步理解。

### Phase 1：立项依据核心（迭代）

**目标**：完成"为什么要做这个研究"的论证。

**执行步骤**：
1. 调用 `write-literature-review` skill，撰写国内外研究现状
   - 基于Phase 0的文献调研结果
   - 按研究主线组织文献
   - 在总结小节中明确列出不足（这些不足将对应项目的研究内容）
2. 调用 `write-research-purpose` skill，撰写研究目的与意义
   - 基于S2中指出的文献空白，论证问题的必要性和特殊性
   - 确保S1中提出的核心问题与S2中的不足形成呼应
3. **迭代检查**：
   - S1中提出的问题是否在S2中有文献支撑？
   - S2中指出的不足是否在S1中被回应？
   - 如不一致，返回修订
4. 可能需要回到S4补充特定方向的文献

**产出**：S1初稿 + S2初稿（两者逻辑一致）。

### Phase 2：价值论证

**目标**：完成"做了有什么用"的论证。

**执行步骤**：
1. 调用 `write-application-prospects` skill
   - 学术价值应对应S2中指出的方法/认识不足
   - 工程价值应紧贴S1中描述的现实条件
   - 行业实际问题应与项目研究内容对应
2. 检查S3中声称的价值是否在S1/S2中有铺垫

**产出**：S3初稿。此时立项依据部分（S1+S2+S3+S4）基本完成。

### Phase 3：研究方案纲领

**目标**：将立项依据转化为具体的研究任务。

**执行步骤**：
1. 调用 `write-research-objectives` skill
   - 研究目标应直接回应S1中提出的核心问题
   - 研究内容应覆盖S2中指出的不足
   - 关键问题应精确对应每条研究内容的"最难部分"
2. 可配合 `write-key-problems` skill 深化关键问题的论证
3. **回溯修订**：此时可对S1/S2/S3做最终修订
   - S1中的核心问题表述是否与S6的研究目标一致？
   - S2中的不足是否被S6的研究内容完全覆盖？
   - S3中的价值声称是否能在S6中找到对应？

**产出**：S6初稿。立项依据部分最终定稿。

### Phase 4：研究方法

**目标**：为每条研究内容设计具体的技术方案。

**执行步骤**：
1. 调用 `write-research-methods` skill
   - 每条方法严格对应S6中的一条研究内容
   - 方法设计应体现S9中将声称的创新点
   - 数学建模和算法设计应具体、可操作
2. 确认S4中的文献引用是否覆盖了方法部分需要的引用

**产出**：S7初稿。研究方案的技术核心完成。

### Phase 5：收尾

**目标**：完成剩余部分，形成完整的申报书。

**执行步骤**（以下可并行推进）：

**S9 特色创新点+计划+成果**：
1. 调用 `write-innovation-plan` skill
   - 创新点应源于S7中方法设计与已有工作的差异
   - 年度计划应覆盖S6中所有研究内容
   - 预期成果应回应S3中声称的价值

**S8 可行性分析**：
1. 调用 `write-feasibility` skill
   - 技术储备论证应与S7方法相关
   - 研究条件应支撑S7的实验需求

**S5 研究基础/条件/指导教师**：
1. 调用 `write-research-foundation` skill
   - 基于用户提供的真实信息填写
   - 前期成果应与S6研究内容有关联

**产出**：S5 + S8 + S9初稿。全部section初稿完成。

### Phase 6：全文审查

**目标**：确保各section之间逻辑一致、衔接流畅。

**审查清单**：

| 检查项 | 涉及section |
|--------|-----------|
| S1提出的核心问题 → S6研究目标 → S7研究方法 → S9创新点，是否形成完整链条 | S1→S6→S7→S9 |
| S2指出的不足 → S6研究内容 → S7方法设计，是否一一对应 | S2→S6→S7 |
| S3声称的价值 → S9预期成果，是否能兑现 | S3→S9 |
| S4文献引用 → 正文中每个引用标记都有对应条目 | S4↔全文 |
| S5前期成果 → 与S6研究内容相关 | S5→S6 |
| S7方法所需条件 → S5/S8中确有相应条件 | S7→S5/S8 |
| 全文术语、表述风格是否一致 | 全文 |
| 总字数是否符合申报要求 | 全文 |

## 迭代修订规范

### 何时触发迭代

1. **Phase内迭代**：S1↔S2之间的互相修订（Phase 1）
2. **跨Phase回溯**：后续Phase发现前置section需要调整
3. **用户反馈**：用户对某个section提出修改意见

### 迭代修订原则

- **向后传播优先**：如果修改了S1的核心问题，应检查S6/S7/S9是否需要相应调整
- **最小修改**：迭代修订时尽量只修改受影响的部分，不推倒重来
- **版本意识**：每次迭代后提醒用户确认，避免反复修改引入不一致

## 状态管理

### 跟踪每个section的完成状态

在撰写过程中，维护以下状态信息：

```
S1: [未开始/进行中/初稿完成/已定稿]
S2: [未开始/进行中/初稿完成/已定稿]
S3: [未开始/进行中/初稿完成/已定稿]
S4: [未开始/进行中/初稿完成/已定稿]
S5: [未开始/进行中/初稿完成/已定稿]
S6: [未开始/进行中/初稿完成/已定稿]
S7: [未开始/进行中/初稿完成/已定稿]
S8: [未开始/进行中/初稿完成/已定稿]
S9: [未开始/进行中/初稿完成/已定稿]

当前Phase: [0-6]
文献引用编号范围: [1-N]
```

### 断点续写

如果会话中断，可以通过以下方式恢复：
1. 检查项目目录下已有的文档文件
2. 读取已有文档内容，判断完成状态
3. 从未完成的section继续

## 注意事项

1. **不要跳过Phase 0**：文献调研是整个申报书的基础，没有充分的文献支撑，后续所有论证都缺乏说服力
2. **不要把S1和S2视为完全独立**：它们是互为迭代的，强行一次性写完任何一个都可能导致逻辑不一致
3. **S4是持续性任务**：不是"写一次就完"的，每个Phase都可能需要补充新文献
4. **S5高度个性化**：必须基于申请人真实信息，不能编造
5. **S6是核心枢纽**：它承接立项依据、开启研究方案，是最关键的承上启下环节，值得花最多时间打磨
6. **S7是技术含量最高的部分**：数学公式和算法设计直接影响评审对项目可行性的判断
7. **全文审查不可省略**：各section分开撰写容易产生不一致，最后必须做全文一致性检查
8. **尊重用户的节奏**：不要一口气写完所有section，每个Phase完成后应与用户确认再继续
